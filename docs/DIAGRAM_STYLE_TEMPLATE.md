# Diagram Style Template

This template keeps AI Infrastructure Trading Advisory Workstation diagrams consistent across README images, architecture docs, future specs, and agent-generated assets.

The visual goal is quiet, operator-grade clarity: warm paper background, precise labels, restrained color, and no marketing composition. Diagrams should make product boundaries and implementation ownership obvious before they try to look decorative.

## Visual System

Use this style for generated PNGs and for any future Mermaid/SVG equivalents.

- Canvas: 1536 x 1024 PNG for README-scale diagrams.
- Background: warm off-white, approximately `#f8f6f1`.
- Text: charcoal, approximately `#232426`.
- Secondary text: muted gray-brown, approximately `#5a554f`.
- Borders: thin charcoal, 1-2 px.
- Corner radius: 8-18 px depending on object size.
- Shadows: none or very subtle; avoid glossy depth.
- Layout density: dense but readable, with clear lanes and consistent spacing.

Preferred palette:

| Role | Color | Use |
| --- | --- | --- |
| Evidence / storage / neutral system | `#dceaf1` | SourceSignal, EvidenceItem, API, PostgreSQL, UI |
| Reasoning / analyst objects | `#dcead8` | MarketEvent, SegmentImpact, EquityImpactAssessment |
| Advisory / planning | `#f6e7b7` | TradingAdvisory, TradePlan, roadmap next phase |
| Risk / suppression / policy | `#f2d7cf` | RiskRegimeUpdate, forbidden surfaces, suppression |
| Plain neutral object | `#ebe8e2` | Manual journal, outcome review, secondary boxes |
| Callout background | `#f7f9fa` | Invariants and explanatory notes |

## Typography

- Use large exact labels. Do not rely on generated-model text for final labels.
- Use deterministic compositing for labels, endpoint paths, object names, and policy language.
- Prefer title case for diagram titles and object names when matching docs.
- Preserve code/object casing exactly: `MarketEvent`, `SourceSignal`, `TradingAdvisory`, `GET /internal/analyst-brief/latest`.
- Keep explanatory callouts to one or two short lines when possible.

## OpenAI Image Workflow

The project diagram pack uses an OpenAI image-model base plus deterministic label compositing. This keeps the visual tone generated by OpenAI while preventing hallucinated labels, misspelled endpoints, or fuzzy policy language.

Recommended workflow:

1. Generate a low-text base visual with the OpenAI image model.
2. Avoid asking the image model to render final endpoint names or long object labels.
3. Composite exact labels, boxes, arrows, and callouts locally.
4. Inspect final PNGs at original size.
5. Fix any overlap, clipping, or arrow collision before committing.
6. Keep the Mermaid source in `docs/APP_DIAGRAMS.md` for implementation review.

Prompt scaffold:

```text
Create an operator-grade architecture diagram for an advisory-only AI infrastructure trading analyst workstation.
Style: warm off-white paper background, charcoal lines, restrained muted palette, calm Anthropic-adjacent documentation aesthetic, dense but readable.
Composition: clean boxes and arrows, no logos, no people, no stock-market imagery, no broker/order/trade-execution imagery.
Text handling: leave text areas simple; exact labels will be composited later.
Mood: serious product architecture documentation, not marketing, not a hero graphic.
```

## Content Rules

Every diagram must preserve the product boundary:

- Advisory and reporting only.
- No broker integration.
- No live order placement.
- No automated trading.
- No execution endpoint.
- No execution UI.
- Manual trade journal only.
- LLMs extract, classify, summarize, review, critique, and explain.
- Deterministic code owns schemas, validation, evidence linkage, readiness, risk checks, accounting, PnL, position weights, target weights if used, and audit lineage.

## Layout Rules

- Product loops read left to right.
- Runtime diagrams show ownership: external sources -> worker -> database -> API -> UI.
- Data lineage diagrams keep audit objects visibly attached to the objects they create or gate.
- Boundary diagrams use two-column comparison.
- Readiness gates read top to bottom and fail closed.
- UI maps show the primary analyst path first, then supporting views.
- Roadmaps show status, artifact, and test ownership.

## Avoid

- Decorative blobs, gradient orbs, bokeh, stock-photo motifs, or trading-floor imagery.
- Broker, order ticket, exchange, execution, or automated trading visuals.
- Dense paragraphs inside boxes.
- Text smaller than README readers can inspect.
- Mermaid-only README orientation when a PNG is available.
- Generated text as the final source of truth.

## Review Checklist

Before committing a diagram update:

- Does the README point to the OpenAI PNG, not an obsolete image?
- Are exact labels deterministic and readable?
- Are arrows and labels free of overlap?
- Is the advisory-only boundary visible?
- Are forbidden execution paths absent or explicitly marked forbidden?
- Does `docs/APP_DIAGRAMS.md` still contain the implementation-readable Mermaid source?
- Did `git diff --check` pass?
