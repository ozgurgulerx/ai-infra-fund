# AI Infrastructure Fund Agent Instructions

## Source Of Truth

Read this file first, then the relevant files under `docs/specs/` and `docs/plans/` before changing code.

If a plan and a spec conflict, stop and resolve the conflict before implementation continues.

## Non-Negotiable Rules

- No live order placement or broker execution endpoint.
- The product is advisory-only.
- LLMs may extract, summarize, classify, review, and explain.
- Deterministic code owns scores, risk, backtests, constraints, and target weights.
- Business logic must not hard-code model names.
- Model routing must use `config/model_profiles.yaml`.
- PostgreSQL + pgvector owns all v1 durable records, semantic retrieval, market snapshots, backtest summaries, evaluation results, and audit state.
- DuckDB + Parquet is a future optional analytical scale-out path only, not a v1 dependency.
- Docker Compose is the v1 runtime boundary with separate `web`, `api`, `worker`, `postgres`, and `migrate` services.
- Every recommendation must include evidence IDs, model run IDs, target weights ID, signal bundle ID, and advisory-only labeling.
- TargetWeights must be generated by deterministic portfolio code, not directly by an LLM.
- Cloud model calls must respect data-class routing rules.
- Private reports and secrets must never be committed.
- Do not leak `.env` contents: never print, paste, summarize, commit, or copy local environment files or secret values into logs, docs, prompts, tickets, model inputs, or generated artifacts. Use `.env.example` for documented placeholders only.

## Cloud Deployment Policy

- Treat this repository as the cloud-deployed codebase. Changes should target the code paths, container boundaries, configuration, migrations, and deployment manifests that run in cloud, not a disconnected local-only fork.
- After implementation and verification, deploy the updated stack to cloud unless the user explicitly asks for local-only work or a dry run.
- Cloud deployment must still respect all guardrails: no secrets in git or logs, no `.env` leakage, no broker/order execution surface, and no deployment before the required tests and checks are green.
- When cloud and local behavior differ, document the difference and prefer fixing the cloud path first.

## Required Workflow

Use phase-scoped implementation.

1. Read the relevant specs.
2. Write or update tests first.
3. Run the tests and confirm the intended failure.
4. Implement the smallest scoped change.
5. Rerun targeted tests and architecture policy tests.
6. Report files changed, tests run, verification result, and remaining gaps.

Phase 0 is governance and scaffold only. Do not implement ingestion, trading logic, backtests, recommendation generation, or a product UI during Phase 0.
